1 · Process

How a contract gets approved today, and with Klauzula AI

The lawyer still decides at every point. Klauzula AI removes the queue and the check against the playbook from memory: the lawyer reviews a ready report and answers one question, "any red flags?".

5 · Observations from building the skeleton

What we learned

The process removed a screen

In the TO-BE process a new version is just another round. Compare stopped being a tab and became part of the review. Round 2 now uses the same mode as round 1, so rules and AI never disagree about what changed.

The decision belongs to the lawyer

The tool counts red flags but does not say "safe to sign". If the lawyer signs with open red flags, the report records that the risk was accepted.

"Polish law" is bigger than it looks

The diagram promises an analysis against Polish law. We deliver a reference to the statute behind each playbook rule. A real check of mandatory law needs a source base and a radca prawny; an AI must not invent article numbers.

Names: cues work, signatures do not

"Represented by Jan …" is now masked. A bare name on a signature line is not. A proper name recogniser is still needed before a pilot.

Sales is a user too

Edits go to the counterparty through sales, so the report needs a plain "edits to send" list, not only legal reasoning. Sending it from the tool (email, Teams) is the next question.

Lawyers still live in Word

A new version arrives as tracked changes; we read it as if all changes were accepted. Reading and writing real tracked changes in .docx is the most important next step. AI accuracy on a test set is still not measured.
