# Требования и спецификация v0.1

Продукт: **Klauzula** (рабочее название, [ADR-0005](decisions/0005-product-name-klauzula.md)).
Тип договора для MVP: **NDA** ([ADR-0003](decisions/0003-mvp-contract-type-nda.md), статус proposed).
Пользователь: in-house юрист средней польской компании ([ADR-0002](decisions/0002-positioning-poland-in-house.md)).

## 1. Пять функций MVP

| # | Функция | Что делает | Ценность для юриста | Статус в v0.1 |
|---|---------|-----------|---------------------|---------------|
| F1 | Загрузка и разбор договора | DOCX / TXT / вставка текста → пункты (§) с номерами и заголовками | Не нужно копировать текст вручную | ✅ готово |
| F2 | Маскирование персональных данных | E-mail, телефон, PESEL, NIP, KRS, IBAN заменяются метками до анализа | Снимает главное возражение (81% боятся за данные) | ✅ частично: имена людей не маскируются |
| F3 | Проверка по плейбуку компании | Каждое правило → OK / Review / Red flag, цитата пункта, объяснение | Красные флаги видны за секунды, не за 30–60 минут | ✅ правила (demo); 🟡 Claude-режим — код есть, не протестирован |
| F4 | Предложение правок и решение юриста | Резервная формулировка из плейбука; юрист правит, принимает или отклоняет | Готовый текст для ответа контрагенту; решение остаётся за юристом | ✅ готово |
| F5 | Сравнение версий и отчёт | Сравнение версии A и B по пунктам + какие риски появились / ушли; экспорт отчёта в Word (.doc) и Markdown | Быстрый ответ на «что они поменяли»; отчёт для бизнеса | ✅ готово (track changes в DOCX — нет) |

Что **не** входит в v0.1: вход в систему, хранение истории, редактор плейбука в интерфейсе, надстройка для Word, другие типы договоров, польский интерфейс.

## 2. Функциональные требования

| ID | Требование | Функция | Приоритет | Статус |
|----|------------|---------|-----------|--------|
| FR-001 | Загрузка .docx и .txt до 5 МБ, вставка текста | F1 | Must | ✅ |
| FR-002 | Разбиение на пункты по нумерации «1.», «1)», «§ 1»; без нумерации — по абзацам | F1 | Must | ✅ |
| FR-003 | Маскирование e-mail, телефонов, PESEL, NIP, KRS, IBAN до отправки текста в LLM | F2 | Must | ✅ |
| FR-004 | Маскирование имён и адресов физлиц | F2 | Should | ⬜ |
| FR-005 | Одна находка на каждое правило плейбука: уровень, пункт, точная цитата, объяснение | F3 | Must | ✅ |
| FR-006 | Подсветка пункта в тексте договора по клику на находку | F3 | Should | ✅ |
| FR-007 | Отсутствующий пункт помечается как «missing» | F3 | Must | ✅ |
| FR-008 | Правка редактируется; кнопки Accept / Reject / Copy | F4 | Must | ✅ |
| FR-009 | Сравнение двух версий по пунктам: added / removed / modified, пословный diff | F5 | Must | ✅ |
| FR-010 | Список изменений рисков между версиями (New risk / Improved) | F5 | Must | ✅ |
| FR-011 | Экспорт отчёта с решениями юриста: Word (.doc), Markdown | F5 | Must | ✅ |
| FR-012 | Экспорт правок как track changes в .docx | F5 | Should | ⬜ |
| FR-013 | Работа без LLM (rule-based режим) для демо и тестов | F3 | Must | ✅ |

## 3. Нефункциональные требования

| ID | Требование | Метрика / критерий | Статус |
|----|------------|--------------------|--------|
| NFR-001 | Конфиденциальность | Текст маскируется до LLM; договоры не сохраняются на сервере; модель не обучается на данных | ✅ v0.1 ничего не хранит |
| NFR-002 | Хранение и обработка в ЕС | Хостинг и LLM-обработка в ЕС | ⬜ решить при выборе хостинга |
| NFR-003 | Скорость | Проверка NDA ≤ 60 с (Claude), ≤ 1 с (правила) | ✅ правила: < 0,1 с |
| NFR-004 | Прозрачность | Каждая находка содержит дословную цитату и ссылку на пункт | ✅ |
| NFR-005 | Human-in-the-loop | Дисклеймер на каждом экране и в отчёте; ничего не отправляется контрагенту автоматически | ✅ |
| NFR-006 | Измеримость | Время проверки «до/после» фиксируется в пилоте | ⬜ нужен пилот |
| NFR-007 | Простота запуска | Прототип запускается одной командой без установки пакетов | ✅ `python3 app/server.py` |

## 4. Критерии приёмки v0.1 (проверено автотестами `app/tests`)
- Образец `nda_counterparty_v1.txt` → 6 красных флагов (право, суд, бессрочность, исключения, штраф, non-solicitation).
- Образец v2 → право и срок OK, появился новый риск NDA-07 (indemnity).
- Сравнение v1 → v2 показывает удалённый § 6 и один новый риск.
