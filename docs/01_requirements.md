# Требования и спецификация v0.2

Продукт: **Klauzula AI** ([ADR-0006](decisions/0006-product-name-klauzula-ai.md), proposed).
Тип договора для MVP: **NDA** ([ADR-0003](decisions/0003-mvp-contract-type-nda.md), proposed).
Пользователь: in-house юрист средней польской компании ([ADR-0002](decisions/0002-positioning-poland-in-house.md)); получатель отчёта — бизнес (продажи / закупки).
Процесс: TO-BE из [03_architecture.md](03_architecture.md), раздел 2. Объём v0.2: [ADR-0007](decisions/0007-scope-v0-2-to-be-process.md).

> **0.3.0:** спецификация перестроена по шагам TO-BE. F4 «Правки» и F5 «Сравнение и отчёт» заменены на F4 «Отчёт и решение юриста» и F5 «Новая версия — новый раунд»; в F3 добавлены ссылки на нормы права Польши; FR-004 (ФИО) реализовано частично.

## 1. Пять функций — по шагам процесса TO-BE

| # | Функция | Шаг TO-BE | Что делает | Ценность для юриста | Статус в v0.2 |
|---|---------|-----------|-----------|---------------------|---------------|
| F1 | Загрузка и разбор | Юрист загружает файл в Продукт | DOCX / TXT / вставка текста → пункты (§) с номерами и заголовками | Не нужно копировать текст вручную | ✅ |
| F2 | Маскирование идентификаторов | Маскирует идентификаторы | ФИО, e-mail, телефон, PESEL, NIP, KRS, IBAN → метки до анализа | Снимает главное возражение (81% боятся за данные) | ✅ ФИО по словам-маркерам, в блоке подписей и рядом с должностью; повторы, инициалы и склонения — та же метка; без маркера, должности и вне блока подписей — нет |
| F3 | Проверка по плейбуку и законодательству Польши | Анализирует контракт | Каждое правило → OK / Review / Red flag, цитата пункта, объяснение, **норма права Польши / ЕС** | Красные флаги видны за секунды; видно, на какой норме стоит правило | ✅ правила; 🟡 нормы — примеры, не проверены; 🟡 Claude-режим не протестирован |
| F4 | Отчёт и решение юриста | Генерирует отчёт → Проверяет отчёт → «Есть красные флаги?» | Правка из плейбука редактируется, Accept / Reject; юрист выбирает «на подписание» или «отправить правки»; отчёт для Word / Markdown со списком правок для бизнеса | Решение за юристом; бизнес получает готовый список правок | ✅ (track changes в DOCX — нет) |
| F5 | Новая версия — новый раунд | Новая версия — снова на проверку | Новая версия проверяется так же, как первая, + что изменилось с прошлого раунда и какие риски появились / ушли | Не нужно заново читать весь текст; новый риск виден одной строкой | ✅ |

Что **не** входит в v0.2: вход в систему, хранение истории раундов на сервере, редактор плейбука, надстройка для Word, другие типы договоров, польский интерфейс, анализ императивных норм права Польши вне плейбука, отправка правок из продукта (e-mail, Teams).

## 2. Функциональные требования

| ID | Требование | Функция | Приоритет | Статус |
|----|------------|---------|-----------|--------|
| FR-001 | Загрузка .docx и .txt до 5 МБ, вставка текста | F1 | Must | ✅ |
| FR-002 | Разбиение на пункты по нумерации «1.», «1)», «§ 1»; без нумерации — по абзацам | F1 | Must | ✅ |
| FR-003 | Маскирование e-mail, телефонов, PESEL, NIP, KRS, IBAN до отправки текста в LLM | F2 | Must | ✅ |
| FR-004 | Маскирование ФИО физлиц | F2 | **Must** (было Should: ФИО есть на схеме TO-BE) | 🟡 по словам-маркерам, в блоке подписей и рядом с должностью; повторы, инициалы и склонения — та же метка (образец `nda_counterparty_v3.txt`); имя вне этих мест — нет |
| FR-004a | Маскирование адресов физлиц | F2 | Should | ⬜ |
| FR-005 | Одна находка на каждое правило плейбука: уровень, пункт, точная цитата, объяснение | F3 | Must | ✅ |
| FR-006 | Подсветка пункта в тексте договора по клику на находку | F3 | Should | ✅ |
| FR-007 | Отсутствующий пункт помечается как «missing» | F3 | Must | ✅ |
| FR-014 | У каждого правила плейбука и каждой находки — ссылка на норму права Польши / ЕС (KC, KPC, UZNK, RODO, Rome I, Brussels I bis) с пометкой «to verify» | F3 | Must | ✅ (ссылки — примеры, проверить у radcy prawnego) |
| FR-008 | Правка редактируется; кнопки Accept / Reject / Copy | F4 | Must | ✅ |
| FR-015 | Блок решения «Any red flags?»: число красных флагов, принятых правок и флагов без правки; две кнопки — «ready for signing» / «send edits to the counterparty». Продукт не принимает решение сам | F4 | Must | ✅ |
| FR-011 | Экспорт отчёта: решение юриста, сводка, нормы права, таблица решений; при «send edits» — раздел «Edits to send to the counterparty» для бизнеса. Word (.doc), Markdown | F4 | Must | ✅ |
| FR-012 | Экспорт правок как track changes в .docx | F4 | Should | ⬜ |
| FR-016 | Загрузка новой версии из экрана отчёта как следующего раунда (Round 2, 3…) | F5 | Must | ✅ |
| FR-009 | Изменения по пунктам с прошлого раунда: added / removed / modified, пословный diff прямо в тексте договора | F5 | Must | ✅ |
| FR-010 | Изменения рисков с прошлого раунда (New risk / Improved) — по находкам того же режима (правила или Claude) | F5 | Must | ✅ |
| FR-017 | Чтение track changes из .docx как исправлений (кто и что поменял) | F5 | Should | ⬜ сейчас читается как «все исправления приняты» |
| FR-013 | Работа без LLM (rule-based режим) для демо и тестов | F3 | Must | ✅ |

## 3. Нефункциональные требования

| ID | Требование | Метрика / критерий | Статус |
|----|------------|--------------------|--------|
| NFR-001 | Конфиденциальность | Текст маскируется до LLM; договоры не сохраняются на сервере; модель не обучается на данных | ✅ v0.2 ничего не хранит (раунды живут только в браузере) |
| NFR-002 | Хранение и обработка в ЕС | Хостинг и LLM-обработка в ЕС | ⬜ решить при выборе хостинга |
| NFR-003 | Скорость | Проверка NDA ≤ 60 с (Claude), ≤ 1 с (правила) | ✅ правила: < 0,1 с |
| NFR-004 | Прозрачность | Каждая находка: дословная цитата, ссылка на пункт, норма права | ✅ |
| NFR-005 | Human-in-the-loop | Решение «подписать / отправить правки» принимает только юрист; ничего не отправляется контрагенту автоматически; дисклеймер на экране и в отчёте | ✅ |
| NFR-006 | Измеримость | Время проверки «до/после» и число раундов фиксируются в пилоте | ⬜ нужен пилот |
| NFR-007 | Простота запуска | Прототип запускается одной командой без установки пакетов | ✅ `python3 app/server.py` |
| NFR-008 | Достоверность норм | AI не придумывает статьи: ссылки на нормы берутся только из плейбука | ✅ правила; Claude-режим — нормы подставляет сервер из плейбука |

## 4. Критерии приёмки v0.2 (автотесты `app/tests`, 12 тестов)
- Образец `nda_counterparty_v1.txt` → 6 красных флагов (право, суд, бессрочность, исключения, штраф, non-solicitation); имя представителя заменено на `[NAME_1]`.
- Образец `nda_counterparty_v3.txt` → 5 человек, по одной метке на человека; в тексте нет ни одной фамилии, в том числе в блоке подписей, в форме «J. Przykładowy» и в падеже «Przykładowego»; «Alfa Logistics sp. z o.o.», должности и термины договора («Receiving Party») не маскируются.
- У каждой находки есть норма права; у NDA-06 — KC art. 484.
- Образец v2 как раунд 2 → право и срок OK, новый риск NDA-07 (indemnity), § 6 удалён.
- Отчёт с решением «send edits» содержит раздел «Edits to send to the counterparty» с принятыми правками; с решением «sign» — «Ready for signing».
